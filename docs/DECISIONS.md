# Decisions

Choices the spec doesn't make, one per line, with the reason.

- Deployment target macOS 26.0: this Mac runs 26.4, and §13 says to use its major version.
- Bundle ID `com.jmarwane.cue`: personal tool, no team; matches the git user.
- Ad-hoc signing (`CODE_SIGN_IDENTITY "-"`), no hardened runtime: "signed to run locally" (§13) with no developer account needed.
- `Cue.xcodeproj` is generated by `xcodegen generate` and not committed: `project.yml` is the source of truth.
- KeyboardShortcuts pinned to 3.1.0 (latest tag): exact pin keeps builds reproducible without a committed Package.resolved.
- KeyboardShortcuts stores the hotkey in UserDefaults (`~/Library/Preferences/com.jmarwane.cue.plist`): it's the library's own storage, managed by macOS; Cue's own files stay in Application Support.
- Tests use Swift Testing (`import Testing`): ships with Xcode 26, no dependency.
- `ProcessGroup.spawn` uses `POSIX_SPAWN_CLOEXEC_DEFAULT`, default signal handlers and an empty signal mask: children inherit only stdin/stdout/stderr and get normal SIGTERM behavior regardless of Cue's own state.
- stdout and stderr share one pipe: §8 asks for one combined buffer; the stderr-specific "first error line" fallback will need a second pipe in M1.
- Group stop waits until `kill(-pgid, 0)` reports no members (polled every 50 ms): stopping is judged by observation, not by the signal being sent.
- Environment capture reads `/usr/bin/env -0` between markers, each built from two printf pieces: NUL separation keeps multi-line values intact, and split markers can't be printed early by a shell echoing its command line.
- Environment capture drops `_`, `SHLVL`, `PWD` and `OLDPWD`: they describe the capturing shell, not the user's setup.
- Capture accepts the shell's output when both markers are present, whatever its exit code: a zshrc whose last line fails still yields a valid environment.
- After a capture times out, Cue stops that shell's process group: anything left in it was started by the capture itself.
- Capture tests use fixture shells and a temporary `ZDOTDIR` for real zsh: they never read the user's dotfiles.
- Esc in M0 clears the search, then closes the panel: §5's order minus expansions, which arrive in M2.
- The panel also closes when it stops being key (e.g. ⌘Tab): same intent as "a click outside", and avoids a key panel lingering over another active app.
- Panel background is `NSVisualEffectView` (`.popover` material) with a 14 pt continuous corner: "the system material" (§14); it switches to solid with Reduce Transparency on its own.
- Panel height follows the SwiftUI content's intrinsic size, with the top edge pinned under the menu bar: `.preferredContentSize` alone left `fittingSize` at 0 (the M0 "panel doesn't open" bug), and expansions will need resizing anyway.
- Debug aids: `-CueOpenPanelAtLaunch YES` / `-CueSnapshotPath <png>` launch arguments, and in Debug builds a `com.jmarwane.cue.debug` distributed notification (`toggle`, `snapshot:<path>`): lets the panel be exercised and inspected without Screen Recording permission.
- Panel show/close events log at notice level under `com.jmarwane.cue`: makes focus and closing behavior checkable from `log show`.

## M1 · Core

- Every item stores every field; only the fields its kind uses are written: switching kind in the editor keeps what was typed, and items.json stays short enough to write by hand.
- items.json decoding is lenient (only `kind` and `name` required; `runningWhen` accepts `"process"`, `{"port": 4000}` or `{"port": "$PORT"}`, `{"statusCommand": "…"}`; `stopBy` is `"process"` or `{"command": "…"}`; `timeLimit` is seconds or null): M2 reads hand-written files.
- A missing `id` gets a fresh UUID on load: hand-written items work, and the first save makes the ID stable.
- items.json that can't be read, or has a newer `schemaVersion`, is an error, never an empty library: a save must not overwrite data Cue didn't understand.
- Save order: write a temp file in the same folder, copy the current file to `items.json.bak`, then `rename()` into place: the rename is atomic, and the .bak is always the previous good version.
- A secret's value is never encoded, even if set in memory: the Keychain is the only place it lives (§11).
- The tested signature includes non-secret environment values as well as keys: changing `PORT=4000` to `PORT=5000` changes behavior, so it needs a new test run. Secret values stay out.
- Links never need testing (`isTested` is always true): there's no command to test.
- `$NAME` in port and address fields resolves from the item's plain environment variables, then its inputs: a service with `PORT=4000` in its environment can use `$PORT` without an input.
- Separate stdout and stderr pipes feed one bounded buffer: needed for the "else the last stderr line" rule and for a status command's "first line of stderr"; the interleaving between the two streams is approximate.
- Lines over 16 KB are cut into pieces: output with no newlines can't grow a line buffer without bound.
- A carriage return keeps only the text after it: progress bars show their last frame as the last line.
- An empty `::cue result` / `::cue reason` (no text) is ordinary output: there's nothing to show.
- Secrets shorter than 4 characters aren't redacted: masking "1" or "ab" would garble ordinary output. Longest secrets are masked first.
- Exit 127 names the command from the shell's own "command not found: X" when it printed one, else the command's first word: the shell knows which word failed in a multi-line script.
- A process killed by a signal reads `Stopped by signal 9 (Killed)`; durations under a minute read in whole seconds.
- Time limits apply to tasks only: a service is meant to keep running, and status commands have their own 5 s limit.
- The working folder is checked before spawning (`Folder not found: ~/x`), and a secret missing from the Keychain fails the run before it starts.
- A start that doesn't come up in 30 s also stops what Cue launched: leaving it running would make a retry start a duplicate, and Failed shouldn't hide a live process.
- An owned port/status service whose process exits gets one immediate re-check: still On (e.g. `docker compose up -d` handing off) stays On, no longer owned; otherwise Failed `Exited unexpectedly · exit N` plus one unexpected-exit event.
- A start command exiting non-zero while Starting fails at once with its exit message, without waiting out the 30 s.
- Failed stays Failed through Off or Unknown check results; only a passing check replaces it: a failure needs attention until it's acted on, but status mustn't claim Failed for something that is now On.
- Checks retry once before turning On into Off or Unknown (§9 "checks are retried automatically"): a single dropped probe of a busy server isn't a stop.
- Stop on a service Cue doesn't own, with no stop command, changes nothing and returns `notOwned(port:)`: the UI then offers `Stop process on port…` (M6). Never kills by name.
- Stop by command: a failing stop command is `Failed · Stop command failed · Exited with code N`; stop commands get 30 s.
- "Still answering" messages per check: `Still answering on port N`, `Status command still says it's running`, `Still running after Stop`. Force Stop is offered only while Cue owns live processes.
- Port protection between items applies to services Cue is running: starting a second item on a port held by a running Cue service shows `Port N is already in use by <name>` instead of launching (owner lookup via lsof is M6).
- Supervisor reports changes on one `AsyncStream<SupervisorEvent>`: the app's main-actor model is the single consumer.
- Tests use `nc -lk` (in macOS) as a fixture server, and ports below the ephemeral range: parallel tests binding port 0 can't steal a fixture's port.

## M2 · Panel

- Open question §19 (pinned section past ~20 items): took the default, a flat list plus search. You weren't available to ask.
- Row presentation (glyph, subtitle, one-click action) lives in CueCore as pure functions: the §5 one-click table is unit-tested without UI.
- "Checking status…" shows only when there's no earlier result (or after clicking Check on Unknown); routine re-checks keep the last glyph, dimmed if stale: checking every service on each open would otherwise flash every row.
- "Not yet tested" replaces the subtitle only when idle (Off, Ready, Done, Cancelled); Failed, Unknown and running states show their real status: status first.
- Failed subtitle prefers the script's `::cue reason`, then `exit N · first error line`, then the failure message.
- Relative times: `just now` under a minute, then `3m ago`, `2h ago`, `4d ago`; elapsed: `42s`, `4m`, `1h 5m`.
- Error details headline is `Exit 1 · 2m ago` with the error line below it (not repeated), or `<message> · 2m ago` without an exit code.
- Until the milestones that build them, the editor, quick add, Settings and "Stop process on port…" answer with a short toast instead of doing nothing; New Reminder, add and Recent rows aren't shown.
- ⌘K is a native NSMenu opened from the footer: keyboard navigation and VoiceOver come for free; the panel ignores losing key status while it tracks.
- An expansion belongs to its row: activating another row closes it, and ↵ submits it only while its row is selected. Prevents ↵ from running an item other than the selected one.
- Hover selects only after the pointer actually moves: a resting pointer over a re-rendered row stole the selection back from the arrow keys.
- While an expansion is open, hovering doesn't change the selection: a mouse nudge mustn't abandon a half-filled form.
- items.json is re-read when the panel opens, if its modification date changed: supports hand-written files (M2) without moving rows while the panel is open.
- A library that fails to load shows its error in the panel and marks the icon as needing attention; nothing is saved over it.
- The icon needs attention for Failed items and Unknown-with-a-reason; a never-checked service (Unknown, no reason) doesn't count.
- Debug-only aids for testing without Screen Recording: `-CueLibraryDirectory`, and `key:`, `type:`, `click:`, `select:`, `actions` debug notifications that call the same model methods as keys and clicks.

## M3 · Editor and Test Run

- Each item keeps its own draft until Save or Revert; switching items never loses typing, and closing the window keeps drafts for the session (the sidebar dot shows them). No "discard changes?" prompt: nothing is lost by closing.
- A new item is a draft until saved; − on an unsaved draft just drops it. − on a saved item asks first and also deletes its Keychain secrets.
- Removing an item Cue is running is refused (`Stop <name> first`): deleting it would orphan a process Cue owns.
- Name, icon and tint follow the command (and folder) until the user edits them; the name for `npm run dev` uses the folder (`Splash dev`), scripts use their file name, path arguments are skipped.
- Kind for a new command: Service if `dev`, `serve`, `server`, `watch` or `up` appears as a word (so `update` and `backup` don't count).
- "Ask before running" switches on at Save only when the command changed and matches `rm -r` (any recursive flag), `sudo`, `--force`, `git push`, `git reset --hard`; switching it off again sticks.
- The tested signature is stored when a Test Run passes and the saved item has that exact setup; a passing test of an unsaved draft is applied when that draft is saved unchanged.
- Test Run shows the command with inputs as `NAME=value command` (how they arrive), the resolved program (`isn't on Cue's PATH`, or `doesn't exist or isn't executable` for paths), folder and shell, the last output line, then the result.
- A service Test Run uses its own supervisor: check first (already On → "Stop it, then test again", not passed), start and wait for the check, wait out the 3 s "exited right away" window for process checks, then stop and confirm Off. Testing an item Cue is running is refused up front.
- Test Run uses typed-but-unsaved secret values, then the Keychain.
- Validation before Save or Test Run: a name, a command (or link target), a numeric port or `$NAME`, a status/stop command when chosen, input and variable names that are valid shell names, and a value for every secret.
- Exit 127 for a path (`./x.sh`) keeps the spec's `Command not found: ./x.sh` but hints at the path, not the PATH.
- Keychain items: generic passwords, service `Cue`, account `<itemID>.<KEY>`, label `Cue secret <KEY>`. With ad-hoc signing, macOS may ask to allow access again after each rebuild.
- A minimal main menu (Quit, Edit, Close) is installed though never shown: text fields need it for ⌘C/⌘V/⌘A/⌘Z, and the editor for ⌘W.
- Test Run is ⌘R and Save is ⌘S; opening the editor "at Test Run" tints the Test Run button and says "Test it before using it from the menu".
- Closing the editor hides Cue so focus returns to the previous app (Cue has no Dock icon).
- Debug builds with `-CueLibraryDirectory` keep secrets in memory, never in the login Keychain.

## M4 · Quick add

- The add row sits after the matching rows (before Recent), so showing it never moves a row.
- The time-phrase parser is written here (rule 3 needs it); M5 adds its remaining tests and the reminder plumbing. Until M5, ↵ on a reminder add row says so in a toast.
- Times with minutes and no am/pm are 24-hour (`at 9:30` at 15:00 → tomorrow 09:30); a bare hour from 1–11 that has passed this morning but not this evening means the evening (`at 7` at 15:00 → 19:00). Also accepted: `16h30`, `6:45 pm`, `tomorrow 16:15`, `in 30s`, `in 2 days`.
- `tomorrow` with no time means 9:00, matching the `Tomorrow 9:00` chip.
- Links also include `127.0.0.1:port/path`; a bare domain needs a dot and a 2+ letter TLD, and no spaces.
- Rule 4 follows the spec literally: `write the report` is a Command because `/usr/bin/write` exists. Tab fixes a wrong guess.
- A link's name: the last path component, humanized (`/admin` → `Admin`), else the host without `www.`.
- ↵ on a command add row saves it (kind, name, icon guessed; "Ask before running" on for risky commands) and opens the editor at Test Run.
- ⌘↵ run once: a task kept in memory only (the Recent group), counted as tested, with ⌘K Save… (opens the editor on a new draft), Dismiss (when not running), Run in Terminal and Copy Command. A `sudo` run-once goes to Terminal instead.
- Typing in the search field clears a drop's or Tab's decision; the + button with an empty field asks for text instead of showing an empty add row.
- Drops: an executable file becomes its quoted absolute path; a non-executable script with a shebang offers Make executable on ↵ (`chmod +x`, adding execute only where read is allowed) and stays a command; without a shebang, `.sh/.bash/.zsh/.py/.rb/.js/.pl` run through their interpreter, with a note saying so. Anything else, folders and apps become links.
- The menu-bar icon accepts drops through its window's delegate, highlights while hovered, and opens the panel on the add row.
- Needs Terminal: an idle item whose command contains the word `sudo` shows `Needs Terminal`, and its click runs it in Terminal. Failures and running states still show first.
- Run in Terminal: `cd '<folder>' && export K=v; … <command>` via AppleScript `do script`; plain environment variables and inputs are exported (shell-quoted); secrets never are, since they'd land in the terminal history. Every task/service also gets Run in Terminal in ⌘K.
- `NSAppleEventsUsageDescription` added for the Automation permission.

## M5 · Reminders

- Open question §19 (reminders on the iPhone?): took the default, in-app only. You weren't available to ask.
- A reminder becomes fired when Cue notices its time: on time (within 60 s) it reads `Fired at 23:58`; noticed later (Mac asleep, Cue not running) it reads `Was due 14:00`. Cue checks at launch, on wake, and with a timer for the next due time. macOS doesn't tell a background app when a notification is delivered, so this is the honest signal.
- Notifications use a calendar trigger at the due time, with the default sound, actions Snooze 10 min and Done; clicking the notification opens the panel. Pending reminders are re-scheduled at launch (same identifier, so no duplicates).
- Permission is asked the first time a reminder is scheduled; if it's denied, a toast says reminders show only in the panel.
- Snooze makes the reminder pending again, due in 10 minutes. Done (notification), a click on a fired reminder, Dismiss or Cancel Reminder (⌘K) removes it.
- The New Reminder row shows only while the search is empty; the selection starts on the first item, not on New Reminder, so ↵ on open does what it did before.
- In the form, the due time is: a picked chip, else a time phrase typed in the text, else the time being kept. Set is disabled until there's one; a typed phrase is removed from the saved text.
- Fired reminders don't mark the menu-bar icon: the spec ties "needs attention" to items and the library check-up.
- Reminder times read `23:58` today, `tomorrow 9:00`, `Tue 9:00` within a week, else the date. Countdowns read `20 min`, `1 h`, `1 h 5 min`, `2 days`.
- Debug runs with `-CueLibraryDirectory` log notifications instead of scheduling them, so testing never shows a permission prompt.

## M6 · Reliability

- Check schedule: a 5 s tick checks each service whose last check is 30 s old (On or Unknown) or 5 min old (everything else, Failed included). Services never checked wait for the launch check or the panel opening.
- On wake: every service shows Checking at once (keeping its last glyph, dimmed if stale), then after 2 s all are checked; reminders are re-evaluated too.
- running.json follows the Supervisor's owned processes automatically (any change to what it owns updates the file), plus running tasks. Entries carry the PID's kernel start time; at launch only an alive PID with the same start time is ours.
- Relaunch: a recovered service is `On · from last session`, owned and stoppable; its exit is watched with kqueue (it isn't Cue's child, so there's no exit code: `Exited unexpectedly`). A task from the last session reads `Outcome unknown · Cue quit during the run` whether or not its process is still alive; Cue doesn't adopt or kill it.
- Port conflicts: a service with a port check that already answers stays `On · started outside Cue` (§3). A service with another check but a port in its address refuses to start while that port answers: `Port 4000 is already in use by node (pid 4312)`, or the Cue item's name when Cue runs it.
- Stop process on port: looks up the listener with lsof, asks `Stop process on port 4000 (node, pid 4312)?` inline, then SIGTERM to that PID, SIGKILL after 5 s, then the check decides. Never by name, never a process group Cue doesn't own.
- Notifications are silent (only reminders make a sound): every transition into Failed (an unexpected exit is one of them, so it notifies once), and a task that exited 0 after more than 5 s while the panel was closed. Clicking one opens the panel.
- History: every finished run of a saved item (tasks, start and stop commands) is a JSON record in `runs/<itemID>/`, with a `.log` of the redacted output when Keep output is on; only the newest 20 are kept. Removing an item deletes its history. Run-once commands aren't recorded.
- View Log shows the live output while running, else the newest kept log, else the output attached to the last failure or Done. Reveal in Finder selects the log file.
- Launch check-up (also after every save): missing folder, missing or non-executable script, or a program not on PATH shows `Needs attention · <problem>` while the item is idle (dashed-ring glyph, click opens the editor) and marks the icon. Commands starting with `$VAR` aren't checked.
- Quit: the alert lists Cue-owned services by name and counts tasks (`Splash Server and 1 task are still running`), says which On services another manager runs and will keep running, and defaults to Cancel. Stop and Quit stops Cue-owned groups and cancels tasks, then quits. ⌘Q works while the panel or a Cue window is key; Settings gets a Quit button in M7.
- Text built from values uses `Text(verbatim:)`: SwiftUI otherwise formats numbers with the locale's grouping (`port 4 917`) and renders Markdown in script output.

## M7 · Polish

- Settings is a plain window (Cue has no SwiftUI App scene): hotkey recorder, the captured environment's source and PATH with Refresh (also re-runs the check-up), Launch Cue at login (SMAppService.mainApp, off by default, with the approval hint when macOS asks), Play a sound with reminders (on by default), Clear History… (asks first), and Quit Cue. ⌘, opens it from the panel.
- VoiceOver: each row is one button labelled `<name>, <status>. <action>.`; times are spelled out (`running for 4 minutes`, `stopped 1 minute ago`), links read `link to …`, reminders and the New Reminder row read their subtitle, the add row hints Tab.
- Increase Contrast: stronger selection highlight and a 1 pt, higher-contrast panel edge (follows the setting live). Reduce Transparency is handled by NSVisualEffectView (solid background). Reduce Motion: the panel fades without scaling, glyphs fade instead of popping, spinners stop.
- The panel opens in 0.24 s from 97 % scale with a fade; the selection highlight slides (0.14 s) for both keys and hover.
- Light and dark were checked against the §14 tokens with `-CueAppearance light|dark` (Debug only).
- The Swift 6.3.3 compiler crashed on `Binding(set: someMainActorMethod)`; a closure wrapper avoids it.
